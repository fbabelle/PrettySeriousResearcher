# Phase 3 — Experiments & ablations

Where the claims get tested and 30% of effort (and most variable cost) lands. The deliverable is **evidence**: a clean ablation matrix, honest baselines, and results that survive scrutiny — produced on local hardware under real rate limits and a finalized budget. Apply the full [experimental-rigor protocol](references/experimental-rigor.md) before the full run and again during reporting.

## Step 1 — Pre-flight smoke tests = boundary calibration (do this BEFORE any full run)

A smoke test here is **not** "does it run once" — it **discovers the operating envelope and proves robustness**, especially for **cost-triggered services (LLM APIs, data-vendor APIs)**. Run it small and cheap, then read off:

- **Boundary discovery per service.** Measure the real **input/output token-length distribution** for the actual call scenarios — set `max_tokens` from measurement, not a guess. Distinguish **reasoning models** (much larger output budgets, longer/variable latency — verify against the provider's current official model/API documentation) from standard ones. Record per-call **latency** and timeout tolerances for the specific models/providers in this project.
- **Meaningfulness checks.** Confirm function-calling / prompt framings return *useful, parseable* data on the large majority of calls. Measure and drive down **parse-failure** and **excessive-retry** rates; fix schemas/framings until results are reliable. A run that mostly retries or returns garbage is wasted budget.
- **Config robustness.** Validate configs across the scenario spread — long vs short inputs, rate-limit bursts, partial failures, empty/degenerate responses — with sane backoff and retry caps.
- **Outputs feed two consumers.** The measured I/O sizes + latencies + failure rates refine (a) the **throttled/resumable run plan** below and (b) the **cost estimate** that `research-tracking` uses for the **budget-finalization gate**. Record a **go/no-go summary** before the full run is authorized.
- **A mock/fault-injection battery is necessary, not sufficient.** Run it first (free: every role × every injected failure mode → a recovery matrix with valid fallbacks), then run a **live battery** of real calls per (model × role) with realistic contexts under a hard USD cap — only real calls reveal provider contracts. Earned: an all-green mock matrix was followed by three defects in the first 30 real calls: (i) reasoning-capable models spend the *output* budget on hidden reasoning and return an empty body with `finish_reason=length` (classify as truncation → grow the budget; never "fix" it by disabling reasoning — see `research-code-review`); (ii) structured-output schemas must sit in the **intersection** of provider constraints (strict modes want every property declared and required with nullable unions for "optional"; some providers reject an array-of-objects nested in an array-of-objects — keep depth-2 free-form data as strings) and be A/B-verified per provider; (iii) per-cell breaker resets in a battery so one dead role does not hide the others. Start output budgets **generous and unified** (largest observed need + headroom) and narrow from measured maxima; if the provider does not itemise reasoning tokens, budget and price on total output.
- **Validity is not quality — plant ground truth before pinning any capability knob.** A live battery's first-try-valid rate measures engineering health, not decision quality (with reasoning effectively off, every role still returned schema-valid answers), so it cannot choose an effort level, a model or a prompt version. Build a small **planted-truth case bank per role** (cases with a known cause, a transparent oracle for allocations, an ambiguous case whose right answer is *abstain*), score QUALITY against it, and run every knob that was pinned by argument (reasoning effort, context size, memory arm) as a **sweep with the selection rule stated before the data** — and its bias: with ~10 calls per cell a "within one SE of the best" rule defaults to the cheap level on ties, so print the argmax and the full table too, and treat a monotone gradient as the trigger for a confirmatory run on that role only. Agent-authored code is scored by **running** it in a subprocess sandbox on synthetic worlds (discrimination + robustness to empty/NaN input), never by static checks alone; keep the prompt's worked examples out of the case bank — a case that mirrors the example measures copying, not the capability. Earned: effort pins were "high by argument"; the first sweep showed flat quality on allocation roles at 3× the cost and latency, a gradient only on diagnosis, and one probe case contaminated by the prompt's own example. **Three follow-ups the first sweep needed:** (i) a flat curve on an easy case bank is not evidence — add a **difficulty ladder** (graded signal, fewer post-event points, an *unsynchronised* distractor cue) so accuracy can leave the ceiling; (ii) run a **manipulation check** first — a task with exact answers where the knob *must* show (puzzles for reasoning effort): if tokens and accuracy do not move, the setting is not reaching the model (one vendor's levels were inert through the aggregator) and no sweep on it means anything; (iii) the unit of analysis is **model × setting**, not role × setting — the same knob bent one model's curve and left another's byte-identical, so pin per role only after checking per model, and record a per-vendor table as the alternative.

## Step 2 — Probe the local environment & supplier limits

Experiments run on the **user's local machine** — plan around its limits, don't assume a cluster. Probe once and write the findings to `docs/local-env.md` — a **project** doc, not a skill file; the installed skills stay read-only (see `research-repo-hygiene`). Record:

- **Hardware:** CPU cores, RAM, GPU/VRAM (or none), free disk. **Detect the host OS first** (Linux / macOS / Windows) — never assume it; commands, paths, and GPU tooling all differ.
- **Rate limits & quotas:** query the supplier docs for each API in play (LLM provider TPM/RPM tiers, data-vendor request caps, batch windows). Record the actual ceilings.
- **Model prices from the live catalogue, spend from the call structure:** price LLM candidates by querying the provider's model-catalogue endpoint (e.g. a `/models` API) and record the verification date — never from memory or a blog; pick ≥ 2 vendor families with pinned, dated model ids and `seed` support (one open-weight so results survive a closed vendor's retirement); estimate the spend as calls × tokens × cells from the experiment design before the budget gate — in agent-heavy designs the binding constraint is usually agent-active hours, not tokens, and the estimate shows it. **Vendor knobs are not portable:** the same effort label can be silently remapped by one API (one vendor executes `medium` as `high`), so resolve abstract levels per vendor from the vendor's *own* API reference (not an aggregator's page), skip-and-log any arm that would duplicate another, and check the ledger's reasoning-token counts against the label — a "medium" arm spending more reasoning than another vendor's "high" is the tell (earned: a whole verification battery ran one model's "medium" roles at high). Make the runtime realise every abstract pin through that measured map: a level the vendor does not distinguish collapses to the nearest *lower* distinct level, never upward, and the ledger row records the level requested and the level sent — otherwise a "medium" diagnosis silently runs at "high" on one family (one such call spent 37k tokens and 13 minutes). **A catalogue price is a tier:** the cheapest listed endpoint may be a best-effort tier that rate-limits under load, while a standard tier is what actually serves and bills — list the model's endpoints, record which upstream served every call in the ledger, and pin the tier the design and the budget assume (earned: an August price was the cheap tier; every billed row was the standard one, and the "empty replies" were the cheap tier's 429s). **A catalogue entry is not a usable endpoint.** Behind one model id an aggregator may fan out over many hosts with different quantizations and parameter support, and the cheapest host is the one the default route picks: before a family is registered, list its hosts and require the parameters the design depends on (seed, structured outputs, reasoning) at one quantization, route to the qualifying hosts with fallbacks (a single pinned host rate-limits under a ten-call burst), check the account's data policy (an endpoint that trains on prompts can be excluded by a privacy setting and returns 404 as "no endpoint"), and measure availability at the run's cadence — a single-host model that answers half its calls is not a family. Publish the readiness as a table (availability per role, first-try compliance, knob liveness, cost per call) before any cell runs, and record the serving host on every ledger row.
- **Throughput math:** from per-call latency × concurrency-under-limit, estimate wall-clock for the full matrix. If it's days, that's a planning input, not a surprise. **Measure latency per role in the live battery, not per model on a toy prompt** — the cheapest model can be the slowest by an order of magnitude (a 6–13× cheaper model was 14× slower on the diagnosis role: hours vs days per run), which can flip a primary/secondary model choice made on price alone; run different providers in parallel processes so wall-clock is bounded by the slowest, not the sum. **Latency is a distribution over the clock, not a number:** before picking a primary model, probe it at ≥ 3 times of day with a metric that is insensitive to how much it chooses to think (seconds per 1k output tokens) and a decision rule stated before the readings (e.g. worst/best > 4× disqualifies it as the wall-clock-bound primary); a model that is 6 s/kTok at midnight and 130 s/kTok during market hours (one call = 21 minutes) cannot carry a 20-run factorial at any price (earned: the cheapest model lost the primary slot on variability, not on cost or validity).

**Two guardrails on the autonomous runner (adopt from the research-agent harnesses):**
- **Anti-leakage read-only sandbox.** The agent must not be able to tune to the test set, edit the evaluation script, or introduce look-ahead: hold the **datasets *and* the eval/grader script read-only**, run under a non-privileged user, and freeze leakage-resistant splits: by time for temporal targets, or by entity/group when repeated entities could cross partitions. A run that can touch its own grader is a leakage waiting to happen (the #1 finance-ML failure). For finance, `research-finance-rigor` owns the point-in-time/survivorship side of this.
- **Capability containment.** The agent **never self-provisions paid compute, scrapes new data, or signs up for a new paid service without explicit user confirm** — those are budget/legal decisions, not run decisions. Surface them as a gate, don't act on them autonomously.

- **A brokered open-weight model is served by many hosts, and the broker routes on price, not speed.** Hosts of one model differ 5-8x in tokens/s and drift by the hour; pinning the "best-uptime" host can cost a campaign hours per hundred calls (earned: 25 vs 120 tok/s on the same model, 10 h of summed latency on 270 calls). Measure tokens/s per eligible host with one short probe before the campaign and re-measure on a TTL and whenever the chosen host slows; route on the measurement; keep the eligibility filter explicit (declared precision only, required parameters, price ceiling); log every probe as the paid call it is.

## Step 3 — Design the ablation matrix

Turn the Phase-2 candidate variants into a matrix where **each cell isolates one design decision** so its effect is attributable. Include:
- The chosen method, the baselines (incl. honest simple ones), and one-factor-at-a-time variants.
- **Anchor to an established public benchmark** with one comparable headline metric vs *named* baselines (for finance QA: FinQA/ConvFinQA/TAT-QA; for trading/portfolio use `research-finance-rigor`'s leakage-safe infra), plus a **co-primary efficiency/robustness metric** (turnover, capacity, transaction cost, drawdown, latency) — not the headline number alone. Beating only a bespoke metric or a weak baseline is a classic reviewer kill.
- **Prospective analysis plan** — state the estimand, unit of analysis, primary/secondary endpoints, independent sample size, inclusion/exclusion and stopping rules, and a power/precision justification before inspecting final test results.
- **Seeds/repeats** for variance — justify the count and report effect sizes with confidence/credible intervals, not a single run or p-values alone.
- **Dependence and multiplicity plan** — predefine the comparison family; use paired or dependence-aware intervals/tests and one correction matched to the inferential goal. For finance, prefer true out-of-sample/walk-forward evaluation and report Sharpe/drawdown/turnover **after costs**.
- **Evaluation disclosure** — for LLMs record exact model snapshot/date, complete prompts/tool schemas/decoding, contamination checks, judge calibration/blinding, and repeated sampling; for human evaluation record consent/ethics determination, compensation, instructions, rater assignment, and agreement.
- **Agent-facet block (any method with an LLM/agent controller).** A matrix whose cells vary only the statistical/algorithmic machinery reads as "the agent is decoration." Add the agent facets with their canonical isolation: a **controller ladder** (script / algorithmic policy / LLM agent) at **matched budget through the same verifier**; **memory** with none / shuffled / oracle controls (and, whenever outcomes resolve *after* the decisions that produced them, **bi-temporal records read at knowledge time** — an agent memory that can recall an outcome before it was knowable is a leakage channel, so the point-in-time property is a validity test, not a nicety); **verifier integrity × controller adaptivity** (leaky vs frozen evaluator, with a degradation time-course — the highest-signal agent ablation, and the one that turns a validity result into agent evidence); **≥3 model families** with pinned versions and **≥5 seeds** per headline cell (seed noise alone can be ~half the score variance); **counterfactuals as branched live rollouts with common random numbers** — static replay of logged trajectories is invalid once policies diverge; process judges validated against blind human scoring and used as diagnostics, not outcomes. The strongest agent evidence is **one** capability the baselines cannot enumerate (e.g. authoring a new tool/probe on held-out failures), not a wider menu of choices. When that capability is **agent-authored code scored by execution**, the environment must state two things in advance or the score is a property of the model's coding *style*: the **event frequency of the world** in the task text (how many regime flips / restatements a history contains — one family writes guard-heavy instruments whose `events ≥ 2` checks exceed what the world provides) and **how non-readings score** (a NaN reading is a non-reading; count abstained pairs as ties so abstention shrinks discrimination smoothly instead of vanishing). Keep the task's worked examples out of the evaluation bank (an automated prompt lint on the decisive series names), and price interventions with a **transparent constants table whose oracle is the argmax by construction** — unit-test that property before any arm is run (earned: probe-authoring environment, 2026-09-01).
- A descope plan: if the budget/time can't cover the full matrix, which cells are dropped — and **log the descope** (no silent truncation).
- **Decouple powered experiments from LLM spend where the design allows it.** If the method's statistical claims can be evaluated on recorded/replayed/simulated candidate streams (e.g. pre-generated pools instead of live LLM generation), run the powered cells that way and reserve live-LLM spend for the demonstration/system arms — the science budget then barely depends on token prices, which changes the whole budget-gate conversation.

- **A plug-in axis you cannot exhaust (model families, datasets, seeds of a third party) needs a written sampling frame, not a longer list.** Before adding members, fix: the readiness gate a member must pass, the strata the sample must cover (closed/open weights, vendor region, price tier), the budget tiers (headline members run every block, parallel members only the cheap one), pinned dated ids, and the stopping rule (one more member cannot flip the majority). Claims read "k of n members", never "models". A newer version of a pinned model is a *new member* (an optional drift row), never a mid-campaign swap: the within-member join across blocks needs one id, and the finished blocks are sunk cost (earned 2026-09-05: a same-price successor thought 1.7x longer and would have cost a $24 re-run for no scientific gain).

## Step 4 — Throttled, resumable, instrumented runs

Local + rate-limited means runs must survive interruption and respect ceilings:
- **Reproducible env:** run every experiment under **`uv`** (`uv run python …`) against the committed `uv.lock` / Python 3.12, so a result can be reproduced exactly on another machine or after a gap — see `research-repo-hygiene`.
- **Resumable:** checkpoint after each cell/batch; idempotent re-runs (skip completed work via a manifest/cache keyed by config hash). A killed run resumes, it doesn't restart. For LLM-driven runs this means a **recording layer keyed by the prompt hash** with an explicit resume switch (existing recording → answered from disk, no network, no spend) and **deterministic contexts** (seed = decision day, canonical rendering), so that (i) a run the user kills by accident continues for free and (ii) a finished cell **replays identically** — the reproducibility receipt reviewers can run offline (earned: a recorded controller cell replayed with every metric identical; a killed pilot was resumed for the price of its unfinished half). The recording layer is only half of resumability; the other half is **what a run leaves on disk**: a run manifest (args, code revision, prompt/version hashes, prices, terminal status, resume history), a progress file rewritten atomically at every checkpoint, and a per-call audit twin of the cost ledger carrying the prompt as sent, the raw reply, the parsed value and the recovery decision — so any number is re-derivable from one call's row. Three rules keep resumes honest: a run directory with a manifest is **refused** without an explicit resume switch (no silent overwrite); a **failed reply is never cached** (a credit-outage 402 sat in the recordings and would have replayed for free as a failure); a replayed reply **costs zero** in the ledger and against the cell cap. A batch of paid cells is launched by **one launcher that owns it** (parallelism, per-cell logs, idempotent skip of complete cells, stop on credit) — twenty hand-typed commands lost eight cells to an outage nobody was watching. **Recording policy: record every reply, reuse only answers, replay everything.** A failed first attempt and its repaired second one are two recordings a replay must reproduce, so failures are recorded; a *resume* answers from disk only when the recording is an answer (text, no error, no broken stream); a *replay* serves whatever was recorded. Deleting failed recordings looks like hygiene and breaks replay fidelity. A change to the recovery classifier is a trajectory change: replay-identical is a receipt for the code that recorded the run, so disclose classifier changes instead of expecting old recordings to replay under them.
- **Timestamped output directories, never fixed paths.** Every run writes to its own `runs/<name>/<timestamp>/` — a re-run that overwrites a fixed `results.json` silently destroys the previous round's evidence (including instructive *failed* rounds, which are often worth reporting). Applies to spikes too, not just campaign runs.
- **Throttled:** concurrency capped to the measured rate limit; exponential backoff on 429/5xx; for LLM bulk work consider the **Batch API** (50% cheaper, async) and **prompt caching** (cache-read ≈ 10% of input) — both are budget levers from `research-tracking`.
- **Instrumented:** every API call logs its `usage` (input/output/cache tokens, optional explicit `usd`, `model`, `phase`) to `runs/usage.jsonl` — this is the **source `research-tracking` prices for the experiment LLM API cost** (the metered, gated spend), distinct from the coding-agent subscription and the transcript-derived effort numbers. Local-model runs log compute-hours instead (cost ≈ electricity/amortization, entered into `cost.json`).
- **Retry logic is two-tiered, and the ledger is append-only.** Tier 1 is rule-based and always on: classify every failed call (transport / rate-limit / auth-credit / empty / truncated / unparseable / schema / semantic / refusal) and map each class to **one** recovery action (backoff, grow budget, repair prompt with the exact validator errors, reframe, breaker trip, degrade to a validated fallback); write the decision into the attempt's own ledger row (**decide, then log** — an in-place rewrite of "the last row" truncated nested rows and was replaced). Tier 2, an LLM triage agent, is opt-in, consulted **once** only after rule repairs are exhausted for a content failure, constrained to a fixed action menu that cannot drop decision-critical context, and **off in experiment arms** — an LLM in the recovery path masks the controller under study and breaks replayability; its own failure falls back to tier 1, never to a third model. **Size the retry window to a provider blip, not to a network hiccup:** a blip lasts minutes, so five attempts inside half a minute degrade a cell whose prompt answers normally a little later; and an HTTP 200 with an empty body is an upstream failure in disguise — pull the provider's error object / native finish reason into the ledger row, or the audit cannot say why. When one call exhausts its window, **pause the cell** (a terminal "provider unavailable" status that the batch launcher re-queues after a cool-down), never serve the decision from a fallback — a fallback decision is contamination, and a rate-limited provider is not the controller under study; trip the breaker on consecutive *degraded calls*, never on the attempts of one call (one stubborn prompt once turned 128 decisions into fallbacks). A stalled process with no open socket is blocked locally — dump its stack before blaming the provider.
- **Bounded self-debug, not open tree search.** When a run errors, allow a **capped repair loop** (a fixed max-debug-depth, then abandon the cell and log it) and keep a **scored best-program/best-config buffer** that seeds the ablation variants — the useful, bounded pieces of the experiment-search engines. Do **not** run a full best-first agentic tree search over the config space: for AI+Finance the binding constraint is data licensing / leakage / cost-realism, not a huge hyperparameter search, and the extra unattended autonomy works against the confirm-surface the gates provide.
- **Review gate between batches.** Treat the run path as batches with a gate between them, independent of the budget tripwire: before the next paid batch, re-run (i) the audit consistency check on every new run directory, (ii) the data manifest's content hashes, (iii) a cross-process determinism check of the framework, (iv) the cost reconciliation — and read a handful of audited calls by eye (prompt rendered as intended, reply parsed as intended; automated checks prove consistency, not sense). Record the gate's result with a date; a FAIL is fixed and re-gated before anything new is launched (earned: user rule after a mid-block outage and a tracking gap were both found late).
- **Campaign hardening (each earned in a real multi-week campaign):** a **credit/quota watchdog** — check remaining supplier credits/quota before and during long campaigns, don't discover exhaustion mid-run; **back up the official result stores before any destructive rerun or migration** (a one-command backup script, run before, not after); **re-execution at the smallest unit** — support re-running a *single* cell/round in place (with the repaired code, same config hash) so one bad record doesn't force a campaign restart.
- **Dataset/API licensing check (any domain, not just finance):** before a dataset or data API enters the matrix, record that its license/ToS permits research use and whether results/excerpts can be redistributed (into `docs/local-env.md` alongside the rate limits). Finance-facing data additionally goes through `research-finance-rigor`'s licensing/point-in-time checkpoint.
- After writing harness/run code, **invoke `research-code-review`**.

- **A run you kill on purpose is a status change, not a process exit.** Mark its manifest terminal with the reason ("interrupted: superseded by ...") at kill time; a later gate cannot tell a paused run from a crashed one and will fail the stage on it (earned: two superseded runs failed the stage gate a day later).

- **Size a block from measurements, never from a derivation.** Before the first paid cell on a new environment: (1) run the free arms end to end (mock controller, scripted baselines) and check the referee/judge actually *acts* — admissions, alarms, retirements > 0; an analytic delay estimate can be off by an order of magnitude (earned: the formula said a real factor needs four years to be admitted; the free run admitted 199); (2) run ONE live cell and read its call mix and cost — the mix changes with the data (real data fired as many diagnoses as allocations, doubling the per-cell cost); (3) multiply, compare with the live balance, and set the launcher's balance floor so the block pauses — new cells stop, running ones finish, a marker names the shortfall and the resume command — instead of dying on a 402 mid-way.
- **Same-policy forks report three layers.** With a replayed prefix and a live tail, compare outcome metrics, the decision sequence, and the raw reply text separately: an LLM under pinned seed and temperature 0 was never byte-identical in words, agreed on ~80 % of decisions, and produced identical outcomes under a frozen judge (earned 2026-09-05). The layers are the evidence that recordings, not decoding, are the reproducibility mechanism, and that a difference between two LLM arms is not decoding noise.

## Step 5 — Capture results honestly

**When a pre-registered criterion fails, read the audit rows before writing the verdict.** Locate the failure in the mechanism — here, both families authored the same correct instrument and read it correctly, and diverged only in turning the reading into an intervention — and report it as such: per-condition signs, the pre-registered sensitivity rows, the mechanism with the exact audited calls. A metric invented afterwards that rescues the claim is exploratory by definition and is labelled so; the registered criterion's outcome stays the headline (bounded, 1/2 families).

**Audit the ruler before the powered run.** Run the environment-audit checklist in `research-code-review` on the evaluation environment itself before the first paid cell, not after a result looks odd; the owner will ask "is the ruler precise?" and the answer must already be a dated document. **Persist what the hypothesis is about, and build the report before the runs.** If a hypothesis speaks of a time-course, persist the time-course per run, not only end-of-run metrics; the report tool implements every pre-registered statistic (the multiplicity correction, paired intervals, the curve and its slope) and is dry-run on mock cells before the first paid cell. Both were found missing only at a stage review; the recordings made the fix free — the second reason to record everything.

Persist raw outputs, and generate the derived tables/figures through **`research-visuals`** (figures-as-code from `runs/`: vector, shared style, no baked-in titles/captions) so they're publication-ready and auditable, not throwaway PNGs. Report negative and null results plainly (the orchestrator's null-result branch is a legitimate outcome, not a failure). If a result looks too good, suspect **leakage** first (the #1 finance-ML failure) — re-verify the temporal split and point-in-time features before believing it. Run the first **`research-provenance` reconciliation here** while the run context is fresh: every headline number must key back to a `runs/` artifact; for finance topics, the number must also clear the **`research-finance-rigor`** statistical battery (deflated Sharpe / PBO / multiple-testing / after-cost). Traceable *and* honest.

## Exit criteria (Phase 3 → 4)

Pre-flight go/no-go and timestamped analysis plan recorded; the planned matrix run (or its descope logged); independent sample size and all attempted conditions disclosed; results reported with effect sizes, justified uncertainty, multiplicity control, and after-cost metrics where relevant; LLM/human evaluation disclosures complete; leakage and contamination checks passed. Then the orchestrator advances to `research-writing`.
